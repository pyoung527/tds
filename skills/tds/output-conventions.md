# TDS Output Conventions

TDS generates docs/specs only in v1. It must not generate production code or scaffold a service codebase.

## Default Output Folder

Use `tds-output/` by default. If it exists and overwrite is not explicitly approved, ask or write to a safe suffixed folder.

## Default Files

- `PRD.md`
- `ERD.md`
- `API.md`
- `PAGES.md`
- `DESIGN.md`
- `ARCHITECTURE.md`
- `IMPLEMENTATION.md`
- `QUESTIONS.md`

## Generated Artifact Headers

```markdown
# <Artifact Name>: <Service Name>

Source brief: <path to service brief>
Generated by: TDS
Scope: Docs/spec generation only
```

## Consistency Rules

- Same entity names across ERD, API, ARCHITECTURE, IMPLEMENTATION.
- Same page names across PAGES, DESIGN, API, IMPLEMENTATION.
- Same actor names across all artifacts.
- Facts, assumptions, and questions are separate.
- Implementation guidance is planning/specs, not code.
