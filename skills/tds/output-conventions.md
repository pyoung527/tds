# TDS Output Conventions

TDS generates docs/specs only in v1. It must not generate production code or scaffold a service codebase.

## Default Output Folder

Use `tds-output/` by default when the user does not specify an output location.

If `tds-output/` already exists:

- ask before overwriting, or
- write to a safe suffixed folder such as `tds-output-2/`.

## Default Files

Generate these files:

- `PRD.md`
- `ERD.md`
- `API.md`
- `PAGES.md`
- `DESIGN.md`
- `ARCHITECTURE.md`
- `IMPLEMENTATION.md`
- `QUESTIONS.md`

## Consistency Rules

- Use the same entity names across `ERD.md`, `API.md`, and `IMPLEMENTATION.md`.
- Use the same page/screen names across `PAGES.md`, `DESIGN.md`, and `API.md`.
- Use the same actor names across all artifacts.
- Keep user-provided facts separate from inferred assumptions.
- Put contradictions, missing decisions, and uncertainty in `QUESTIONS.md`.

## Generated Artifact Headers

Each generated artifact should start with:

```markdown
# <Artifact Name>: <Service Name>

Source brief: <path to service brief>
Generated by: TDS
Scope: Docs/spec generation only
```

## Recommended Output Layout

```text
tds-output/
  PRD.md
  ERD.md
  API.md
  PAGES.md
  DESIGN.md
  ARCHITECTURE.md
  IMPLEMENTATION.md
  QUESTIONS.md
```
