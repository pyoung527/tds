# Architecture: Launch List

Source brief: docs/tds/examples/simple-service-brief.md
Generated by: TDS
Scope: Docs/spec generation only

## System Boundary

Private launch-planning web service with authenticated users, launch/task data, invitation email delivery, and responsive UI. This is architecture guidance only, not an app scaffold.

## Logical Modules

- Auth and Access Control.
- Launch Management.
- Launch Area Management.
- Task Management.
- Readiness Engine.
- Collaboration / Invitations.
- UI Shell for Dashboard, Task List, Task Detail, Settings.

## Data Ownership

Launch owns Launch Areas and Tasks. Founder owns Launch-level management rights. Collaborator permissions are scoped to Launch access. Task assignment references User but does not imply ownership.

## Integration Boundary

Email delivery is isolated behind invitation service boundary.

## Security / Privacy

Launch plans are private by default. Every Launch, Area, Task, and collaborator operation checks launch access. Founder-only operations include invites and Launch Area management.

## Readiness Calculation

Assumption: readinessPercent = completed tasks / total tasks, with blocked tasks shown separately and never counted as ready.

## Deployment Assumptions

Assumption: web-first responsive app; relational storage fits the structured model; async/background path may be useful for email invitations.

## Architecture Risks

Collaborator invite model, multi-launch support, task activity history, and readiness scoring can change data model/API/UX.
